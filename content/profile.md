## 个人简介

### ① 身份与规模

我是张普朝，在北京做 K-12 科创装置的研发与交付。做过 71 项实体装置（33 项有实物且材料成套），覆盖助老助残、消防应急、农业、环境监测、交通、教育等 9 个赛道；沉淀 469 份 Word 文档、2,598 件三维模型、1,450 条原创选题。整条链路通常是我一个人。

### ② 做的事与技术面

主控以 ESP32-S3 与 Arduino 为主，识别用 K210 / K230 部署，执行端有麦轮、机械臂、推杆、水泵与灯带，通信打通 UART、CAN 和 WebSocket。能做出能过现场演示的样机，也能自己写 700–1,500 行固件，连同接线与排障文档一起交付。

### ③ 教育产品化与教研能力

装置之外，我把它做成能开班的产品：2 门课到可印刷水准（4 课时教师手册 185 段 14 表、30 分评价量表），36 次课创造发明课程体系已完成三阶段骨架，每个项目贯通设计、编程、三维建模、电路与装置原理五个模块。赛事侧，我知道这些比赛要交什么、按什么标准打分。

## 能力矩阵（6）

> 评分标准（沿用底稿）：1 听说过 / 只会照抄；2 能跑通别人的东西并改参数；3 能独立做出来，但要查资料、要试错；4 能一次做对，有工程规范；5 能定义方案、能带人、有体系。

### ① 嵌入式整机联调 · 3.5 / 5

**一句话**：能把主控、传感器、四类执行器、上位机和现场排障串成一台真能跑的整机，并把接线与验收写成别人能照着做的文档。

- `follow_pid.ino`：手写 PID，固定 30ms 周期、`dt` 换算秒制、积分限幅 ±300、死区清积分、避障用滞回防抖。
- `actuators.cpp`：IDLE / EXTENDING / HOLDING / RETRACTING 四态非阻塞状态机，全程 `millis()` 轮询，不用 `delay()` 卡主循环。
- `SoilLoose.ino` 单文件 1,264 行打通 WebServer + WebSocket + 4 类执行器 + HX711 称重 + 看门狗；配套 `WIRING.md`（12.9KB）与 `串口测试.md`（46.8KB）两份排障文档。

### ② 交付物程序化生产 · 4.5 / 5

**一句话**：不是"会写文档"，是把文档做成产线——spec → plan → 逐 task 报告 → docx / xlsx / 设计图，同一套模板可以复制到下一个项目。

- 12 个 `gen_*.py` 用 python-docx / openpyxl / matplotlib 生成 BOM、订单、技术书与多视图设计图。
- 14 节点 LangGraph 流水线，4 类文档各配「写 → 审 → 条件重写」回路；`word_io.py`（26.6KB）+ `docx_style.py`（7.7KB）把 Word 样式、图注、编号、表头做深度封装。
- 84 份论文、42 份研究日志、56 份研究方案同构产出；同一台装置可按 5 个赛事的材料规范分别组卷，这套结构在 8 个交付项目里重复过。

### ③ 技术吸收与移植 · 4.0 / 5

**一句话**：读手册、读规则原文、读别人的私有格式，几周内变成能跑的东西，并且给得出量化验证。

- `zdt_can.py` 466 行：照 ZDT 电机手册手写 SLCAN 协议——开通道时序、扩展帧收发、独立收线程，注释直接标"手册 4.2.1"。
- `follower_core.h` 399 行：DTW 跟谱算法 Python → C++ 移植，零 Arduino 依赖的测试核心，主机测试台实测 MAE 0.17 拍、98.8% 帧误差 ≤0.5 拍。
- `decompile.py` 208 行反解 MindPlus 的 Blockly 工程格式；K230 部署时把 ImageNet 归一化折进 kmodel 预处理（uint8 + input_range + mean/std）。

### ④ 机器人算法 · 2.5 / 5

**一句话**：会标定、会测精度、会调电流，能做关节空间遥操作；不碰逆解、D-H、雅可比和轨迹规划。

- `arm_control` 全部 10 个 `.py` 无逆解 / 无 D-H / 无雅可比（grep 零命中），只做"关节角度 ↔ 电机脉冲"换算。
- 麦轮只有符号级 `sgn(vy+vx+wz)` 出方向，无编码器闭环、无速度环。
- 但也有验证工具：重复定位 A→B→A 五轮测极差与标准差；力矩预算按 `Ma_Limit` 饱和率判断要不要调电流。

### ⑤ 硬件设计（原理图 / PCB）· 1.5 / 5

**一句话**：强在选型与电气常识，弱在画板——全库没有一块自己设计的 PCB。

- 6 个 PCB / EDA 文件全部位于下载的开源工程 ArmSync 目录内，时间戳统一，属上游产物。
- AI-EDA 项目「词元开物」的 gerber / cam / jlc 目录全是 0 字节 `.gitkeep` 占位。
- 但接线经验是真的：`WIRING.md` 钉死共地、舵机独立 5V ≥3A；土壤松土项目主动避开 ESP32-S3 的 strapping 引脚 0/3/45/46。

### ⑥ 软件工程 · 3.5 / 5

**一句话**：单项目能写出带测试的交付级产品，但不具备"被人接手、持续迭代三年"的工程体系。

- `kechuang-platform`：FastAPI + SQLite + Vue3，65 次 conventional commit、36 个 pytest、13 个 vitest，`vue-tsc` 类型检查进构建门禁。
- 全库 90 个项目 0 个 CI、仅 7 个 PlatformIO 工程、6 个 git 仓库，只有 2 个项目有主机端单元测试。
- 数据层是 JSON-in-SQLite：无 ORM、无迁移、无索引；核心固件普遍 700–1,500 行单文件。

## 差异化优势（3）

### ① 一个人闭环：7 个环节，从选题到交付

选题 → 方案 → 三维 → 电路 → 固件 → 文档 → 答辩材料，7 个环节一个人走完，71 项装置是这条链路的物证。多数人只在其中一个环节工作，真正的缺口不是能力，是把它们串起来。

### ② 把交付物做成产线，而不是靠加班堆

12 个生成脚本 + 14 节点流水线 + 84 份同构论文 + 同一台装置 5 种组卷方式，单月 18 台是这套产线的结果。同类硬件工程师里，能把文档和排版自动化到这个程度的不多。

### ③ 三种语言都能讲：技术方案、赛事材料、课程手册

一台装置，我能写成给工程师看的技术方案与 BOM，写成给评委看的申报包，也写成给老师用的教师手册和 30 分评价量表。技术、赛事、课程三套话术打通，是这个岗位真正的稀缺点。
